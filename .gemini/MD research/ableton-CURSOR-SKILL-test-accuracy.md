# Adversarial Accuracy Test — Ableton Live 11 Cursor Skill

## Verdict

**SHIP-WITH-FIXES**

The skill gets the most important compatibility fence right: the installed `user-AbletonMCP` tool `create_audio_clip` is explicitly Live 12.0.5+, while `duplicate_to_arrangement` is documented by that server for Live 11/12. Its operational MCP inventory also matches the currently discovered server.

It is not ready to ship unchanged. One Python LOM entry point is malformed, the Remote Script framework is incorrectly presented as an official API pattern, the supplied `.als` parser is unsafe for untrusted or unexpectedly large files, and several privacy, threading, latency, edition, and exact-version claims are too strong.

Scope note: the two requested files were not present at the exact paths supplied. The files found and tested were:

- `cursor edit/ableton-research-agent-CURSOR-SKILL.md`
- `cursor edit/ableton-research-agent-ANALYSIS.md`

The third cross-check source, `ableton research and automation agent.md`, was present at the requested location.

| 1 | “`.als` = gzipped XML” in the Live 11-scoped skill. | VERIFIED | PRONOM identifies Live Set files from 8.2.1 onward as GZIP-compressed XML; reverse-engineering tools agree. This is accurate for Live 11. The format is undocumented and non-contractual, which the skill also states. [PRONOM](https://www.nationalarchives.gov.uk/PRONOM/Format/proFormatSearch.aspx?id=2286&status=detailReport) | Keep, but phrase as “Live 11 `.als` files are observed to be gzip-compressed XML; this is not a supported interchange format.” |
| 2 | The sample `gzip.open(...).read()` → `ET.fromstring(...)` is a suitable parsing template. | RISKY | It reads the entire decompressed Set into memory with no compressed-size, expanded-size, nesting, or element-count limit. Python warns that its XML modules are unsafe for maliciously constructed data and separately calls out decompression bombs. [Python XML security](https://docs.python.org/3/library/xml.html) | Stream with an expanded-byte cap and `iterparse`, reject oversized/deep documents, catch `BadGzipFile`/parse errors, and use `defusedxml` when accepting untrusted Sets. |
| 3 | Offline `.als` mining can derive “scene launch workflows” and “launch patterns.” | RISKY | A saved Set exposes Session clips, slots, scenes, launch settings, and arrangement state, but it is not an execution log. It cannot establish which scenes the user actually launched or in what sequence unless an explicit history artifact exists. | Rename to “saved Session layout and launch settings”; label behavioral workflow inference as heuristic and require corroborating logs or repeated-set evidence. |
| 4 | “Offline = `.als` XML only (+ exported MIDI/audio on disk).” | WRONG | The skill itself later includes `Backup/`, `Samples/`, `Presets/`, M4L devices, User Library paths, manuals, and production notes. Ableton also documents `.asd`, `.amxd`, `.adv`, `.alc`, and other local file types. This is an internal contradiction. [Ableton file types](https://help.ableton.com/hc/en-us/articles/209769625-Live-specific-file-types) | Say “Offline Live-state inspection is limited to saved artifacts; `.als` is the primary Set artifact, supplemented by explicitly selected local project/library files.” |

| 7 | “No project/set/telemetry off-machine unless user opts in,” while directing use of this MCP. | RISKY | Every installed operational tool exposes an optional `user_prompt` described as being “for telemetry.” Discovery does not reveal whether telemetry stays local or leaves the machine. The skill does not tell the agent to omit/redact this field or verify the server implementation. | Default `user_prompt` to omitted/empty; inspect the installed server’s telemetry destination before sending user text; disclose and obtain opt-in before any off-machine telemetry. |
| 8 | Remote Script entry: `Live.Application.get_document()` → `Song`. | WRONG | The known Python form is `Live.Application.get_application().get_document()`. Inside a `ControlSurface`, the normal framework accessor is the surface’s `song`/`song()` API depending on framework generation. The stated static call omits `get_application()` and is an invented/malformed entry point. [Example source](https://github.com/dinchak/LiveOSC/blob/master/LiveUtils.py) | Replace with version-checked code: `Live.Application.get_application().get_document()`, or use the exact accessor exposed by the selected Live 11 ControlSurface framework. |
| 9 | Python MIDI Remote Scripts are an “Official pattern”; subclass `ControlSurface` as directed. | WRONG | Ableton officially documents installation and the Python 3 requirement, but it does not publish or support the internal `_Framework` / `ableton.v2` / `ableton.v3` programming API. Ableton explicitly says it cannot support third-party scripts. `ControlSurface` is real, but the framework surface is private/version-sensitive, not an official stable SDK. [Ableton installation guidance](https://help.ableton.com/hc/en-us/articles/209072009-Installing-third-party-remote-scripts) | Call Remote Scripts a supported extension mechanism with an undocumented/private Python framework. | 10 | A Remote Script “lives in `MIDI Remote Scripts/`.” | RISKY | For third-party scripts Ableton recommends a `Remote Scripts` folder inside the User Library. [Ableton installation guidance](https://help.ableton.com/hc/en-us/articles/209072009-Installing-third-party-remote-scripts) | Say “install third-party scripts under `<User Library>/Remote Scripts/`; do not modify the application bundle unless exact-version bridge instructions explicitly require it.” |

## Top risks

1. **Invented Python API call:** `Live.Application.get_document()` will mislead generated Remote Script code; the application singleton step is missing.
2. **Unsafe parser template:** an adversarial or merely huge `.als` can exhaust memory through unbounded gzip expansion and whole-tree parsing.
3. **False API stability signal:** calling `ControlSurface` an official pattern hides that the Python framework is private, unsupported, and exact-build-sensitive.
4. **Incorrect execution model:** “audio thread” language obscures Live’s deferred main-thread LOM behavior, observer mutation restrictions, and the special role of `live.remote~`.
5. **Privacy ambiguity:** all discovered MCP tools include an optional telemetry field, directly conflicting with the skill’s strict local-only promise unless it is omitted or audited.
6. **Missing exact-version/edition/Max gate:** Live 11.0 vs 11.2 vs 11.3, Intro vs Standard vs Suite, macOS plug-in support, and Max 8 licensing materially change valid advice.
7. **Overclaiming offline behavior:** saved XML can reveal structure and settings, not actual scene-launch history, runtime audio behavior, or authoritative plug-in state.
